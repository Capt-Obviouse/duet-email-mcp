# Story: EML-002 Skeleton: app, auth seam, account config, credentials seam, audit, `list_accounts`

**Epic:** none
**Layer:** backend, infra
**Estimate:** L
**Priority:** P1
**Status:** In Review
**Visual:** none
**Assign to:** Developer (then QA and Security: auth, credentials and deploy are touched)

## Description
As the operator, I want a deployable skeleton with account configuration, a credentials seam,
an audit line and `list_accounts`, so that every later mail tool is built on guardrails that
already exist and are tested.

## Locked decisions
- Founding decisions in `CLAUDE.md`, and sections 3 to 6, 7.1, 7.5, 9 (server instructions), 10.1
  and 13 of `docs/architecture/EML-001-architecture.md`.
- Same stack as the sibling calendar bridge: Python 3.12, FastAPI + Mangum (lifespan off), AWS SAM,
  arm64, official `mcp` SDK in stateless streamable-HTTP JSON mode, imported lazily on the first
  `/mcp` request.
- API key: SSM SecureString `<prefix>/api-key` created by the operator (CloudFormation cannot
  create SecureStrings), `X-API-Key` or non-JWT `Authorization: Bearer`, `hmac.compare_digest`.
  Client id `api-key`, **read only unless `client-limits` grants `draft`**.
- Credentials: **one JSON secret** (A591) `{"<alias>": "<app password>"}`, created empty by the
  stack, filled by the operator with the CLI, read lazily and cached per container.
- No IMAP code (EML-003b), no sanitiser (EML-003a), no Cognito (EML-005). The verifier seam stays
  pool-agnostic.
- Lambda: 1024 MB, 30 s, reserved concurrency 5 (parameter), no VPC, Function URL auth NONE.

## Acceptance Criteria
- [x] `GET /health` (and `HEAD`) is unauthenticated and touches neither SSM nor Secrets Manager.
- [x] Every other path, including `/mcp`, `/docs` and `/openapi.json`, rejects a missing or wrong
      key with 401; an unconfigured key is 503; `EnableApiKey=false` rejects the key with 401.
- [x] A JWT-shaped bearer is never compared with the API key; with no verifier configured it is 503.
- [x] The verifier has the SDK `TokenVerifier` shape (`async verify_token -> AccessToken | None`).
- [x] The key client gets `mail.read` only by default; `client-limits` `"access": "draft"` adds
      `mail.draft`; a limit never grants a scope the token lacks.
- [x] `accounts` parser fails closed: missing, blank, unparsable JSON, duplicate keys, unknown
      fields, wrong types, bad alias, bad port, `tls` other than `implicit`/`starttls`, generic
      without `imap`: no mailbox at all. `{}` (the stack default) means no mailbox.
- [x] `client-limits` parser fails closed: missing, unparsable, duplicate keys, unknown fields,
      unknown `access`: no access for any client. Limits only narrow; `"accounts": []` locks out.
- [x] `MailBackend` protocol with result dataclasses; every method takes a required `allowed=`
      keyword; `FakeBackend` in tests implements it.
- [x] Credentials reader: one `GetSecretValue` per 15 min per container, only on first need,
      values wrapped so `repr`/`str` are redacted, never logged (including on parse errors).
- [x] `list_accounts` returns only the caller's effective accounts, with `account`, `address`,
      `description`, `folders`, `search` and `access`, and makes no network call.
- [x] One audit JSON line per tool call (`event`, `ts`, `client_id`, `auth`, `tool`, `account`,
      `status`, optional `error_class`, `ms`) and nothing else; a canary test proves no argument
      value or secret reaches any log line.
- [x] Tool errors are fixed categories (section 7.5) that never echo submitted values.
- [x] Server instructions text from section 9 is sent on `initialize` (tested for presence).
- [x] SAM template: `Accounts`, `ClientLimits`, `EnableApiKey` parameters; accounts and
      client-limits SSM parameters; empty credentials secret; IAM limited to the prefix, the SSM
      managed key and the one secret ARN; `sam validate --lint` passes; `sam build` is arm64.
- [x] Hash-locked `src/requirements.txt` for aarch64 manylinux; `pip-audit` clean.
- [x] Unit tests cover new functionality
- [x] CHANGELOG.md `[Unreleased]` updated
